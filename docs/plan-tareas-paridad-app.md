# Plan: tareas iguales en la web y en la app, y rediseño de las pantallas de la app

Fecha: 2026-10-26. Contexto: la API (`/api/v1/tareas-outlook…`) ya cubre casi todo lo que hace la web; lo que falta está en la **interfaz de la app**.
El modelo de datos es el mismo (`tareas_outlook`), así que «corresponderse» es sobre todo una cuestión de **mismas vistas, mismos filtros, mismas acciones y mismas palabras**.

## 1. Qué tiene la web y qué tiene la app hoy

| Área | Web | App hoy | Hueco |
|---|---|---|---|
| Vistas | Mi día · Lista · Tablero · Calendario · Carga · Informes | Lista + «Hoy» (bandeja general, no es «Mi día») + calendario antiguo | **Mi día** (vencidas / hoy / en progreso / asignadas / compartidas), **Tablero**, calendario nuevo |
| Filtros de la lista | ámbito (mías, asignadas, compartidas, todas), estado, prioridad, categoría (Outlook), texto, «ver también completadas», **vistas guardadas** (proyecto, cliente y persona están en el alta y en las acciones masivas, no en los filtros de la lista) | ámbito, estado, texto | prioridad, categoría, completadas, vistas guardadas |
| Alta | texto libre: «viernes 10h pedir extractos @luis !alta #IVA» (`app/quickadd.py`) + formulario completo | asunto + fecha | **mismo texto libre**; formulario con prioridad, proyecto, cliente, asignar |
| Fila de tarea | estado, prioridad, vencimiento, cliente, proyecto, subtareas, comentarios, cronómetro, «espera a…», solo lectura, compartida | asunto, fecha, estado | indicadores y cronómetro |
| Ficha | descripción, subtareas, checklist, comentarios, adjuntos, **dependencias, recordatorios, compartir/asignar, tiempo y cronómetro, revisión, clientes vinculados, visible para el cliente, conversaciones con el cliente, actividad, proyecto/sección, estimación** | subtareas, checklist, comentarios, adjuntos, bloqueo | todo lo resaltado |
| Acciones masivas | marcar varias → completar, estado, prioridad, vencimiento, asignar, proyecto, sección (`/tareas-outlook/lote`) | no hay | selección múltiple |
| Papelera | eliminar → papelera → restaurar → eliminar definitivamente | no hay | eliminar y restaurar |
| Plantillas, recurrentes, reglas de vencimiento, automatizaciones | sí | no | solo consulta y activar/desactivar (no editor completo) |
| Sin conexión | — | cola de escrituras + caché de lectura (hecho) | ampliar a las nuevas acciones |
| «Deshacer» | solo «restaurar» de la papelera | no | **esta fase** |

## 2. Reglas para que se correspondan (se cumplen en cada fase)

1. **Mismos nombres**: «Mi día», «Lista», «Tablero», «Calendario», «Carga», «Vencidas», «Vencen hoy», «En progreso», «Asignadas a mí», «Compartidas conmigo». Los textos salen de las mismas cadenas (ARB ↔ `messages.pot`).
2. **Mismas reglas**: la app no replica reglas de negocio; las aplica el servidor (bloqueo por dependencias, subtareas abiertas, revisión pendiente, permisos). La app muestra el motivo que devuelve la API.
3. **Un endpoint por vista**: si la web calcula algo en el servidor (Mi día, tablero, carga), la app lo pide a la API en una llamada — no lo reconstruye. `GET /mi-dia` ya existe en la API (mismas cinco secciones que la web): la app solo tiene que pintarlo.
4. **Una prueba de paridad**: `tests/test_paridad_tareas_app.py` compara, para un mismo usuario con datos sembrados, lo que devuelven la pantalla web y el endpoint de la API (mismas tareas, mismo orden, mismas secciones). Si alguien cambia la web y no la API, falla.
5. **Cada acción nueva** nace con: operación en el SDK generado, cola sin conexión si procede, «Deshacer» si es reversible, y test.

## 3. Fases

**Fase 0 — «Deshacer» (hecha, 2026-10-26).**
Completar / cambiar de estado, desde la lista y desde la ficha: aviso «Tarea completada · Deshacer» (6 s). Si el cambio aún estaba en la cola sin enviar, se retira de la cola; si ya se envió, se vuelve al estado anterior con la versión actual (si alguien más la tocó, se avisa en vez de pisar).
Después: eliminar (papelera) con «Deshacer» = `POST /tareas-outlook/{id}/restaurar`.

**Fase 1 — La lista igual que la web (hecha, 2026-10-26).**
Filtros de prioridad, categoría y «ver también completadas» (por defecto se ocultan, como la web), vistas guardadas compartidas con la web (`/tareas-outlook/vistas`), alta con texto libre (`texto_libre` en `POST /tareas-outlook`, que reutiliza `quickadd.py`; API 1.6), filas con proyecto, comentarios, checklist, «espera a…» y quién la asignó, selección múltiple con acciones en lote (completar, estado, prioridad, vencimiento) y eliminar a la papelera con «Deshacer». Prueba de paridad: `tests/test_paridad_tareas_app.py` (9 combinaciones de filtros, misma lista y mismo orden que la web). Pendiente de esta fase: llevar al modo sin conexión las acciones en lote y el eliminar (hoy exigen red).

**Fase 2 — Mi día y Tablero (hecha, 2026-10-26).**
La pestaña Tareas abre en la Lista y tiene el selector **Mi día · Lista · Tablero** (como el submenú de la web). «Mi día» pinta las mismas cinco secciones que la web (30 por sección y «Ver las N restantes») y completa con «Deshacer»; el Tablero tiene una columna por estado (en el orden de la web, completadas recientes 15, 25 tarjetas y «Mostrar más»), con barra de pasos, y mover una tarjeta con «Deshacer» (sin «En revisión» como destino). API 1.7: indicadores en `/mi-dia` y tablero, `?recientes=`. Pruebas de paridad: sección a sección y columna a columna contra la web. «Hoy» sigue siendo el resumen de todos los módulos (su enlace a «Mi día» queda para la Fase 5).

**Fase 3 — La ficha completa (hecha, 2026-10-26).**
**Hecho:** editor completo (asunto, descripción, prioridad, estimación, inicio/vencimiento con hora, categoría Outlook, proyecto, cliente, otros clientes, visible en el portal y comentarios del cliente, asignar a), «Espera a», «Compartida con», recordatorios, «Tiempo dedicado» con cronómetro (iniciar, pausar, reanudar, parar; cuenta con la hora del servidor), tiempo del equipo y actividad, y la cabecera con proyecto, cliente, persona y estimación. **3c, hecha:** revisión (pedir a hasta cinco personas en los tres modos, votar con nota, retirar, historial), conversación con el cliente (leer, contestar, ocultar comentarios) y % completado. La web no tiene «sección» en el formulario de la tarea (solo en el proyecto y en las acciones en lote), así que no aplica. **No incluido:** los adjuntos que el cliente sube a la conversación (se verán en la web).

**Fase 4 — Calendario y Carga (hecha, 2026-10-26).**
El selector de vistas es ya el de la web: Mi día · Lista · Tablero · Calendario · Carga. **Calendario:** mismas cuatro vistas (día, semana laboral, semana, mes), mismas capas que se encienden y apagan (tareas, vencimientos fiscales, citas, fichajes) y mismo reparto de tareas por día (vencimiento o, si no hay, inicio); sale de la misma función que la web (`GET /tareas-outlook/calendario`, API 1.7). Se crea una tarea en un día desde el «+» del día. **Carga:** una tarjeta por persona con sus horas por día frente a la jornada (verde/ámbar/rojo con los umbrales de la web), atrasadas y sin fecha; tocar una celda lista sus tareas y desde ahí se reasigna a otra persona o se cambia/quita el día (lo que en la web es arrastrar). Pruebas de paridad: calendario y carga contra la web. Se corrigió además el formato de `dias` en `GET /tareas-outlook/carga` (salía como fecha HTTP).

**Fase 5 — Rediseño visual de toda la app (hecha, 2026-10-27).**
*Hecho:* se mira cómo se ve de verdad con capturas del tema y las fuentes reales (`CAPTURAS=<carpeta> flutter test test/tareas_test.dart --plain-name captura`). Tema: chips y botones segmentados con selección tonal (el texto claro sobre lima sólido no se leía en oscuro), casillas redondas, tarjetas de 16 px. Tareas (Lista, Mi día, Tablero, Calendario, Carga y Ficha) y «Hoy»: pestañas con subrayado, una sola fila de filtros, tarjetas con barra de prioridad y píldoras de estado/vencimiento/proyecto, deslizar para completar con «Deshacer», columnas del tablero en píldoras, ficha en tarjetas, urgencia de «Hoy» escrita (no solo en color). **Color de acento por persona** en Ajustes (los ocho de la web; cálculo de contraste idéntico al del servidor, con test de paridad) y corrección del contraste del acento como texto sobre el fondo gris real (también en la web). Prueba con la letra al 160 % sin desbordes.
*5c, hecho:* **Fichaje** (estado grande con «desde las…», solo las acciones que valen ahora, semana con los días rotulados, línea de tiempo de hoy) y **Correo** (bandeja con una fila de píldoras y buscador redondeado, filas con avatar/remitente/asunto/principio y lo no leído marcado con palabras; lectura con remitente arriba, responder/reenviar a mano y las acciones secundarias plegadas).
*5d, hecho:* **Asistente IA** (vacío con sugerencias en tarjetas; lo tuyo a la derecha con el acento, lo del asistente en tarjeta con su icono, lo que hizo por detrás en píldora —con icono si falla—, acción pendiente como tarjeta con «campo: valor» y No / Sí, hazlo; entrada redondeada; la voz es opcional y si falla el chat sigue), **barra inferior** (indicador tonal, etiquetas siempre visibles, filo superior) y **«Más»** (accesos en tarjetas con su icono).
*5e, hecho:* **Login** (sin el nombre duplicado en la barra, errores en un aviso con icono), **Ajustes** (agrupados en tarjetas: perfil · apariencia con tema, color de los botones e idioma · asistente, correo · servidor y bloqueo · cerrar sesión), **Redactar** (enviar y descartar en la barra), **Fichaje** (historial por días en tarjetas con el rango en píldoras; datos), **Ausencias** (saldo con barra y cada ausencia en tarjeta con su estado escrito y las fechas como en el resto de la app) y los botones flotantes sin sombra.
*Accesibilidad:* pruebas con las pautas de Flutter (zonas táctiles ≥ 48 dp, nombre para el lector de pantalla y contraste del texto) en Tareas (Lista, Mi día y Tablero, claro y oscuro), Fichaje, Correo y Asistente IA; detectaron el campo de alta rápida de 47 dp, ya corregido. Prueba en tableta (820 × 1180) sin desbordes en las cinco vistas de tareas. *5f, hecho — tableta* (ancho ≥ 720 dp y lado corto > 600 dp; un móvil apaisado conserva el diseño de móvil): barra lateral con etiquetas en vez de la inferior, contenido con ancho máximo (1180 dp en conjunto; 680 dp en formularios y pantallas de lectura), la Lista con la ficha de la tarea abierta al lado (400 dp de lista) y el Tablero con todas las columnas a la vez. **Queda fuera:** una revisión con VoiceOver/TalkBack en un dispositivo real.

**Avisos y búsqueda global (2026-10-27, API 1.8).** *Avisos:* tarjetas con icono de la familia, hora y «Nuevo» escrito (no solo color); píldoras Todos · Sin leer · una por familia con avisos; tocar uno lo marca leído solo a él (`POST /notificaciones/{id}/leida`); deslizar lo quita con «Deshacer» (se borra en el servidor al acabar los 6 s o al salir de la bandeja); aviso de «sin conexión» con la caché; comunicados de la plataforma (`/comunicados`) como franja en Avisos y en Hoy, con «Cerrar» salvo los críticos. *Búsqueda:* campo redondeado, resultados con título, fragmento (lo buscado en negrita), tipo y fecha, píldoras por tipo con contador (Tareas · Notas · Correo · Fiscal), búsquedas recientes (8, en el dispositivo) y hasta 40 resultados. En el servidor, `GET /buscar` ya no devuelve vacío cuando falla el servicio de vectores (Ollama): busca por palabra clave; añade `tipo=` y `titulo`/`fragmento`/`fecha`.

**Notas (2026-10-27, API 1.9).** Pantalla «Notas» en «Más» (y al abrir una nota desde un aviso o la búsqueda): lista con las propias y las compartidas conmigo (fijadas primero), filtros por ámbito y proyecto, búsqueda, tarjetas con título, principio sin marcas, proyecto, «Fijada», «Compartida»/«De Ana», adjuntos y fecha; fijar y borrar desde la lista (deslizar o menú) con «Deshacer» (papelera → restaurar). La nota se lee con el mismo Markdown que la web (negrita, cursiva, listas, enlaces) y se edita con título, texto y una barra de formato; nueva nota sin conexión va a la cola. Con permiso: compartir con compañeros (puede editar / solo lectura), salir de una nota compartida, vínculos (cliente, tarea, correo) que se abren, y adjuntos (foto, galería, archivo). Un colaborador edita texto y título; quien observa solo lee. API: `titulo`/`fijada`/`cliente_fiscal_id` al crear y editar, `GET /notas?compartidas=incluir|solo` con `rol`/`n_participantes`/`n_adjuntos`, detalle también para compartidas, y `POST /notas/{id}/compartir`, `GET .../participantes`, `DELETE .../compartir/{usuario}`. Lectura sin conexión de `/notas` en la caché. Queda para la web: clientes fiscales y tarea/correo vinculados se ven pero no se cambian desde la app.
